Docker와 Apptainer

워크스테이션에서는 Docker, HPC에서는 준비한 SIF 파일로 같은 컨테이너 소프트웨어를 실행합니다.

환경실행 방식준비할 이미지
워크스테이션Docker (기본)로컬 Docker 이미지
HPCApptainer변환한 .sif 파일

longWGS·shortWGS·RNake·KBracken·Humann과 MAGs 세 단계의 실행 스크립트가 두 방식을 지원합니다. GoQC는 Docker, daDake2는 호스트 환경을 사용합니다.

1. 사용할 이미지 확인

docker image ls
docker context show

이미지를 빌드한 워크스테이션에서 확인하세요. 이미지의 CPU 아키텍처는 대상 HPC와 일치해야 합니다.

2. Docker 이미지를 TAR로 내보내기

bash common/Go_container_image.sh export shortwgs \
  container-images/shortwgs.docker.tar

아카이브와 이미지 ID·아키텍처·태그를 기록한 .image.txt를 생성합니다. 컨테이너 파일시스템을 내보내는 docker export 대신 이미지를 보존하는 docker save를 사용합니다.

3. HPC에 이미지와 코드 준비

ssh USER@HPC_HOST 'mkdir -p ~/containers'
rsync -avP container-images/shortwgs.docker.tar \
  container-images/shortwgs.docker.tar.image.txt \
  USER@HPC_HOST:~/containers/

# 아래 명령은 HPC에서 실행합니다.
git clone https://github.com/bbagy/CAULab.git

USER@HPC_HOST를 본인의 로그인 주소로 바꾸세요. FASTQ·참조 DB·GoWGS 자료도 HPC 저장소에 별도로 준비해야 합니다.

4. SIF 파일로 변환

module load apptainer  # 환경에 따라 생략하거나 모듈 이름을 바꾸세요.
cd ~/CAULab
bash common/Go_container_image.sh build \
  "$HOME/containers/shortwgs.docker.tar" \
  "$HOME/containers/shortwgs.sif"

빌드가 허용된 노드에서 실행하세요. HPC에서 변환할 수 없다면 Apptainer가 있는 다른 Linux 환경에서 변환한 SIF를 옮깁니다.

5. dry-run으로 확인하고 실행

apptainer exec --cleanenv "$HOME/containers/shortwgs.sif" snakemake --version
bash ~/CAULab/shortWGS/Go_shortWGS.sh \
  --container apptainer \
  --container-image "$HOME/containers/shortwgs.sif" \
  -i /shared/fastq -o shortwgs_out \
  -d /shared/db/wgs -k /shared/db/kraken2 -r /shared/GoWGS \
  -c 8 -n

실제 경로로 바꾸고, dry-run이 통과하면 -n을 제거해 실행하세요. 할당받은 CPU·메모리에 맞게 실행해야 하며, 이 옵션은 Slurm 작업 분산을 자동으로 설정하지 않습니다.

기록 항목

  • Git 커밋, Docker 이미지 ID와 SIF 체크섬을 기록하세요.
  • 이미지·TAR·SIF 파일은 코드 저장소 밖에서 보관하세요.
  • 실행 스크립트를 복사할 때는 common/container.sh도 함께 배포하세요.
