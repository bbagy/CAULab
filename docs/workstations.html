Docker 내부 환경은 이미지 빌드 시 Micromamba로 생성됩니다. 서버에서 각각 conda activate할 필요 없이 파이프라인 실행 스크립트가 사용합니다. GoQC는 Conda 환경 없이 이미지 안에 Python·Snakemake·fastp·Bowtie2·SAMtools를 직접 설치합니다.

Git과 Docker를 설치하고 Docker를 실행합니다. Ubuntu server에서는 Docker Engine을 설치하고 서비스를 실행합니다. 아래 명령은 코드를 $HOME/CAULab에 받고, 실행 파일을 $HOME/caulab-pipelines에 설치하며 모든 컨테이너 이미지를 빌드합니다.

git clone https://github.com/bbagy/CAULab.git "$HOME/CAULab"
cd "$HOME/CAULab"
bash install_docker_env.sh --build-all
source "$HOME/caulab-pipelines/caulab.env"
caulab_usage.sh

이미 같은 경로에 저장소나 설치가 있다면 아래 업데이트 항목을 사용합니다. GoQC·KBracken·Humannake만 준비할 때는 --build-all 대신 --build-core를 사용합니다. daDake2의 호스트 환경과 참조 DB는 다음 항목에서 별도로 준비합니다. 설치 위치를 바꾸려면 --prefix, 대상 CPU 아키텍처를 지정하려면 --platform linux/amd64를 사용합니다.

2. Docker 이미지 빌드

위의 bash install_docker_env.sh --build-all은 코드 설치와 함께 아래 9개 이미지를 모두 빌드합니다. 완료했다면 다시 빌드할 필요가 없습니다. 코드만 설치했거나 특정 이미지를 다시 준비하려면 아래에서 필요한 명령을 실행합니다. Docker가 실행 중이어야 합니다.

source "$HOME/caulab-pipelines/caulab.env"

GoQC

cd "$CAULAB_PIPELINES/GoQC"
docker build -t goqc:caulab .

KBracken

cd "$CAULAB_PIPELINES/KBracken"
docker build --network=host -t kbracken:caulab .

Humannake

cd "$CAULAB_PIPELINES/Humann"
docker build --network=host -t humann:caulab .

longWGS

cd "$CAULAB_PIPELINES/longWGS"
docker build -t longwgs .

shortWGS

cd "$CAULAB_PIPELINES/shortWGS"
docker build --network=host -t shortwgs .

RNake

cd "$CAULAB_PIPELINES/RNake"
docker build -t rnake:1.0 .

MAGs

cd "$CAULAB_PIPELINES/MAGs"
docker build -f docker/Dockerfile.qc -t mags-qc:1.0 .
docker build -f docker/Dockerfile.assembly -t mags-assembly:1.0 .
docker build -f docker/Dockerfile.annotation -t mags-annotation:1.0 .

빌드 확인

docker image ls

goqc:caulab, kbracken:caulab, humann:caulab, longwgs:latest, shortwgs:latest, rnake:1.0, mags-qc:1.0, mags-assembly:1.0, mags-annotation:1.0을 확인합니다. Humannake의 Docker 이미지 태그는 humann:caulab입니다. daDake2는 이미지 대신 다음 항목의 호스트 환경을 사용합니다.

3. daDake2 실행 환경

daDake2는 Docker 대신 호스트의 Snakemake·R을 사용합니다. Miniforge ↗로 Conda를 준비한 뒤 아래 명령으로 전용 환경을 만듭니다.

conda create -y -n caulab-dadake2 -c conda-forge -c bioconda snakemake r-base r-optparse cutadapt
conda activate caulab-dadake2
snakemake --version
Rscript -e 'install.packages("BiocManager", repos="https://cloud.r-project.org"); BiocManager::install(c("dada2", "phyloseq"), ask=FALSE, update=FALSE)'
Rscript -e 'library(optparse); library(dada2); library(phyloseq)'

DADA2 설치 ↗ · phyloseq 설치 ↗

계통수 단계는 이름이 qiime2인 별도 Conda 환경을 사용합니다. QIIME 2 공식 설치 페이지 ↗에서 운영체제에 맞는 환경 파일을 선택하고, 환경 이름을 qiime2로 지정합니다. 아래 명령은 공식 환경 파일을 $HOME/Downloads/qiime2-conda.yml로 저장한 뒤 실행합니다.

conda env create --name qiime2 --file "$HOME/Downloads/qiime2-conda.yml"
conda run -n qiime2 qiime info
conda run -n qiime2 qiime phylogeny align-to-tree-mafft-fasttree --help

분석 시에는 caulab-dadake2 환경을 활성화합니다. FIGARO는 -A 옵션으로 처음 실행할 때 파이프라인이 별도 환경에 설치합니다.

4. 참조 DB 다운로드

분석할 도구의 DB만 준비합니다. 아래의 $HOME/caulab-db는 실제로 생성할 기본 저장 경로입니다. 다른 디스크를 사용하면 DB_ROOT를 해당 경로로 바꿉니다. /path/to/...는 사용자가 지정할 경로이므로 그대로 실행하지 않습니다. 앞 명령에서 오류가 나면 다음 단계로 넘어가지 않습니다.

GoQC · KBracken · Humannake · longWGS · shortWGS · RNake · daDake2 · MAGs

GoQC·KBracken·Humannake DB를 한 번에 받기
source "$HOME/caulab-pipelines/caulab.env"
DB_ROOT="$HOME/caulab-db"
bash "$CAULAB_PIPELINES/download_databases.sh" --db-root "$DB_ROOT" --tools all --threads 8 --bracken-read-len 100 --humann-uniref uniref90_diamond
source "$CAULAB_PIPELINES/config/lab_paths.sh"

--tools all은 숙주·Kraken2/Bracken·HUMAnN/MetaPhlAn DB를 받습니다. WGS·RNake·daDake2·MAGs의 참조 자료는 포함하지 않습니다.

GoQC

DB / 참조 파일저장 위치 · 실행 옵션
숙주 Bowtie2 인덱스 (사람 CHM13 v2.0)$DB_ROOT/host/bowtie2/chm13v2.0/chm13v2.0 → -d

Docker 이미지 goqc:caulab를 먼저 빌드합니다. 다운로드 후 설정 파일에 숙주 인덱스 경로가 기록됩니다. -d에는 폴더가 아닌 인덱스 접두어를 지정합니다. 사람 이외의 숙주라면 해당 종의 FASTA로 Bowtie2 인덱스를 별도로 만듭니다.

CAULab이 $HOME/caulab-pipelines에 설치되어 있고 Docker가 실행 중이면 아래 명령을 터미널에 복사해 실행할 수 있습니다. DB는 $HOME/caulab-db에 저장됩니다. 다른 디스크에 받으려면 DB_ROOT 한 줄을 실제 저장 경로로 바꿉니다. 다운로드는 대용량이므로 저장할 디스크의 여유 공간을 먼저 확인하세요. 앞 단계에서 오류가 나면 다음 단계로 넘어가지 않습니다.

# 1. 기본 경로에 설치된 CAULab 환경 불러오기
source "$HOME/caulab-pipelines/caulab.env"

# 3. DB 저장 위치: 홈 폴더의 caulab-db
DB_ROOT="$HOME/caulab-db"

# 4. ChocoPhlAn, UniRef90, MetaPhlAn DB 다운로드
bash "$CAULAB_PIPELINES/download_databases.sh" --db-root "$DB_ROOT" --tools humann --humann-uniref uniref90_diamond

# 5. 완료 후 DB 경로 설정 불러오기
source "$CAULAB_PIPELINES/config/lab_paths.sh"

# 6. 받은 MetaPhlAn 인덱스 이름 확인 (추가 다운로드 아님)
find "$DB_ROOT/humann/metaphlan4" -maxdepth 1 -name "*.pkl"

Docker 이미지 humann:caulab를 먼저 빌드합니다. 이 파이프라인의 UniRef90 후처리에 맞춰 UniRef90을 받습니다. 다운로드한 .pkl 파일명에서 확장자를 뺀 값을 -I에 지정하세요. 기존 예시의 인덱스 이름과 새로 받은 DB 이름이 다르면 새 이름으로 바꿉니다. 재현 분석에는 동일한 DB 버전을 사용합니다.

위 CARD와 PlasmidFinder 파일은 SRST2 배포본에 포함된 기존 버전입니다. 최신 DB가 필요하면 원본 서열을 SRST2 형식으로 변환해야 합니다. 각 폴더에 사용할 FASTA 하나만 둡니다. 파이프라인은 정렬상 첫 파일을 선택합니다.

mkdir -p "$WGS_DB/MLST/e_coli"
cd "$WGS_DB/MLST/e_coli"
# SRST2가 설치된 환경에서 실행
getmlst.py --species "Escherichia coli#1"

MLST는 SRST2의 getmlst.py 안내 ↗에 따라 종·scheme별로 받습니다. 생성된 allele FASTA와 profiles_csv 표를 함께 보관합니다. 다른 종의 폴더 이름은 워크플로의 종 코드에 맞춥니다. 실행 시 전체 폴더는 -d "$WGS_DB", Kraken2는 -k /path/to/kraken2_db로 지정합니다.

분석 대상 균주의 assembly accession으로 바꿔 받습니다. 압축을 풀고 FASTA와 GFF 경로를 각각 -g, -a에 지정합니다. 두 파일은 동일한 assembly 버전이어야 합니다. Bowtie2 인덱스는 파이프라인이 생성합니다. CLI 없이 NCBI Datasets 웹에서도 같은 파일을 받을 수 있습니다.
