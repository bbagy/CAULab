분석 개요

설치 경로

heekuk_path/
|-- Go_MAGs_QC.sh
|-- Go_MAGs_QC.smk
|-- Go_MAGs_Assembly.sh
|-- Go_MAGs_Assembly.smk

컨테이너 빌드

cd $CAULAB_PIPELINES/MAGs
docker build -f Dockerfile.qc -t mags-qc:1.0 .
docker build -f Dockerfile.assembly -t mags-assembly:1.0 .
docker build -f Dockerfile.annotation -t mags-annotation:1.0 .

품질 관리 실행

Go_MAGs_QC.sh \
  -i /path/to/input_fastqs \
  -o mags_qc_out \
  -d /path/to/bowtie2_host_index/hg38 \
  -c 8 \
  -j 4 \
  -K

조립 실행

Go_MAGs_Assembly.sh \
  -i mags_qc_out/host_filtered_fastq \
  -o mags_assembly_out \
  -d /path/to/checkm_data \
  -c 24 \
  -j 4 \
  -K

주석 실행

Go_MAGs_Annotation.sh \
  -i mags_assembly_out/9_Final_MAGs \
  -o mags_annotation_out \
  -g /path/to/gtdbtk/release220 \
  -e /path/to/eggnog \
  -k /path/to/kofam_scan \
  -c 24 \
  -j 4 \
  -K

CheckM1

CheckM 설치 안내 ↗의 reference data 링크(CheckM DB 다운로드 ↗)에서 아카이브를 받아 압축을 푼 폴더를 지정합니다. longWGS에서 쓰는 CheckM2 DB와 별개입니다. CheckM의 DB 경로 설정은 Assembly 워크플로가 처리합니다.

GTDB-Tk

docker run --rm mags-annotation:1.0 gtdbtk --version

GTDB-Tk 버전별 DB 안내 ↗에서 위 버전에 맞는 full package를 받습니다. 예를 들어 R220은 GTDB-Tk 2.4.0–2.6.1, R232는 2.7 이상에 대응합니다. 압축을 푼 실제 DB 루트를 -g에 지정하고 mash_db/genomic_mash_db.msh가 있는지 확인합니다. 파일이 없다면 해당 버전의 GTDB-Tk 안내에 따라 Mash DB를 준비합니다.

eggNOG

EGGNOG_DIR="/path/to/eggnog"
mkdir -p "$EGGNOG_DIR"
docker run --rm -v "$EGGNOG_DIR":/db mags-annotation:1.0 emapper.py --version
docker run --rm -v "$EGGNOG_DIR":/db mags-annotation:1.0 download_eggnog_data.py -y --data_dir /db

eggNOG-mapper 다운로드 안내 ↗에 따라 컨테이너에 설치된 도구로 받습니다. 현재 워크플로는 EGGNOG_DIR/eggnog_proteins.dmnd를 직접 사용합니다. v3의 버전별 하위 폴더 등 다른 배치로 다운로드되면 그대로 실행할 수 없습니다. 이 경우 v2 호환 이미지·DB를 사용하거나 워크플로 경로를 먼저 맞춰야 합니다.

Kofam

KOFAM_DIR="/path/to/kofam"
mkdir -p "$KOFAM_DIR"
curl -fL https://www.genome.jp/ftp/db/kofam/profiles.tar.gz -o "$KOFAM_DIR/profiles.tar.gz"
curl -fL https://www.genome.jp/ftp/db/kofam/ko_list.gz -o "$KOFAM_DIR/ko_list.gz"
tar -xzf "$KOFAM_DIR/profiles.tar.gz" -C "$KOFAM_DIR"
gzip -dc "$KOFAM_DIR/ko_list.gz" > "$KOFAM_DIR/ko_list"

Kofam 공식 다운로드 ↗의 profiles와 ko_list를 같은 시점에 받습니다. Prokka의 기본 DB는 컨테이너에 포함됩니다.
