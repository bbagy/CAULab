실행 방법

# 16S V3V4 — multiple projects
DB="/media/uhlemann/core4/DB/DADA2/Bacteria/silva_nr99_v138.1_wSpecies_train_set.fa.gz"
dirs="ProjA,ProjB,ProjC"
smk="$CAULAB_PIPELINES/daDake2"

Go_daDake2.sh -t standard_V3V4 -i $dirs -d $DB -s $smk -c 8 -K
# Zymo V1V2
Go_daDake2.sh -t zymo_V1V2 -i "ProjA,ProjB" -d $DB -s $smk -c 8 -K
# ITS
DB_ITS="/media/uhlemann/core4/DB/DADA2/Fungi/sh_general_release_dynamic_29.11.2022.fasta"
Go_daDake2.sh -t illumina_ITS -i "ProjA,ProjB" -d $DB_ITS -s $smk -c 8 -K
# dry-run
Go_daDake2.sh -t standard_V3V4 -i "ProjA" -d $DB -s $smk -n

실행 시 참고 사항

  • DATE is fixed at pipeline launch (yymmdd) and baked into all filenames — rerunning on a different day never overwrites prior outputs.
  • Small samples (< -m bytes) are written to failed.csv at DAG construction time before any rules run.
  • Samples with zero reads after filterAndTrim are appended to failed.csv and excluded from downstream steps.
  • Host removal (NA phylum, Chloroplast, Mitochondria) applies to 16S types only.
  • addSpecies() is not used; no species DB needed.
  • Mapping template CSVs (3_map/) are generated for 16S types only.
  • qiime2 tree step calls conda run -n qiime2 qiime ... directly.
  • Lock errors are auto-handled by the wrapper (--unlock then retry).

참조 DB 준비

DB / 참조 파일저장 위치 · 실행 옵션
16S: DADA2 형식 SILVA training FASTA압축된 silva_nr*_train_set.fa.gz → -d
ITS: UNITE training FASTAGeneral FASTA · All eukaryotes → -d

DADA2 공식 training DB 목록 ↗에서 16S는 SILVA, ITS는 UNITE를 선택해 연결된 배포 페이지에서 받습니다. SILVA 원본 전체 서열이 아니라 DADA2용 training set을 사용합니다. UNITE는 General FASTA의 All eukaryotes 파일을 선택합니다.

Go_daDake2.sh -i /path/to/fastq -o /path/to/output -d /path/to/silva_nr138.2_train_set.fa.gz

위는 16S DB 지정 예시이며, ITS 분석은 기존 ITS 실행 옵션과 UNITE 파일을 사용합니다. 선택한 DB의 버전과 파일명을 분석 기록에 남깁니다. 현재 실행 스크립트는 species DB를 따로 전달하지 않으므로 addSpecies()용 파일은 필수가 아닙니다.
